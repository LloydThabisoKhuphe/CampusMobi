# db — the data tier

```
db/
  init/                 The 4 files actually run against MySQL, in
                         filename order — everything the schema and demo
                         data consist of.
  gen_app_seed.py        Generated 04_app_seed.sql (kept for
                         reproducibility; not run automatically).
```

## db/init

Mounted into the MySQL container at `/docker-entrypoint-initdb.d` (see
`docker-compose.yml`) and run automatically, in filename order, the very
first time the container's data volume is created — never again after
that, so restarting the container normally does not re-run these or touch
existing data. For a shared/remote database (no container involved), the
same four files are run once by `scripts/db-remote-init.mjs`.

| File                     | What it does                                                                 |
|--------------------------|-------------------------------------------------------------------------------|
| `01_catalog_schema.sql`  | Creates the real WSU Faculty of Natural Sciences catalog tables (departments, qualifications, modules, timetable slots, fee schedule). |
| `02_catalog_seed.sql`    | Populates that catalog: 3 departments, 32 real qualifications (real WSU programme codes), 134 real module codes/credits transcribed from the 2021 Faculty of Natural Sciences Prospectus, curriculum mapping, prerequisites. |
| `03_app_schema.sql`      | Creates the app's operational tables: the real 1,000-entry roster (gates registration), `users` (including `personal_email`, used for OTP delivery), `sessions`, `otp_codes` (registration/login/password-reset), `payments`, `module_enrollments`. |
| `04_app_seed.sql`        | The generated 1,000-student roster, their module enrollments and timetable sections. Generated by `../gen_app_seed.py` (kept for reproducibility) — re-running it needs a running MySQL instance to read the catalog from. |

To reset the demo data back to this initial state: `npm run db:reset`
(local Docker) or `npm run db:remote-init` (shared/remote database) from
the project root.

## gen_app_seed.py

Not run automatically — it's what originally *produced* `04_app_seed.sql`.
Kept one level up from `init/` since it's provenance, not something MySQL
executes (`docker-entrypoint-initdb.d` only runs `.sql`/`.sh` files).
